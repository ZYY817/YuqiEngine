# 宇奇引擎 YuqiEngine — 本次修复与改进说明

> 对应提交：`c661b62`（main 分支）
> 验证状态：构建 0 警告 0 错误；自动化测试 **1656 通过 / 0 失败**
> 目标平台：Windows 10 2004 (19041) 及以上 / Windows 11，中文与英文系统

本次是对全软件的系统性审计与修复：逐页检查所有功能、逐项核实注册表操作、修复中文/英文系统下的读取失效、打通恢复链路、重做部分界面。以下按类别列出所有更新点。

---

## 一、计划任务：修复"状态不可读"全灭

**问题**：后台任务页 16 项全部显示"状态不可读"，功能完全不可用。

**根因**：`schtasks /XML` 输出声明 UTF-16 但实际按控制台 OEM 代码页吐字节，程序用 UTF-16 解码产生乱码，找不到 XML 头 → 所有任务被判"不存在"。

**修复**：
- `schtasks` 输出改为 OEM 代码页优先解码 + UTF-16 回退，真实任务状态恢复可读
- 实测验证：修复前 6 个已存在任务全部读为"不存在"，修复后全部正确读到 `Exists=True Enabled=True`
- `pnputil`（设备页）同款编码问题同步修复，"拒绝访问"检测在中英文系统都生效
- 应用启动时统一注册代码页 provider，消除所有 `GetEncoding` 冷启动失败的隐患（powercfg、netsh、ipconfig 等 5 处）

## 二、中文/英文系统适配（本地化安全）

**问题**：多处功能按英文显示名称/输出文本匹配，在中文系统上永不命中或误判。

**修复**：
- **设备能力**：所有设备定义补充语言无关的 `DeviceIdPrefix`（`ACPI\PNP0100`/`UMB\UMB_BUS`/`ROOT\COMPOSITEBUS`/`ACPI\PNP0103`），WMI 按 Name+DeviceID 双匹配，中文系统不再全灭
- **触摸板修复**：`Name LIKE '%touchpad%'` → `PNPClass='Mouse'`（WMI 类名是英文常量）
- **GPU 虚拟设备识别**：英文名称关键词 → 增加 `PNPDeviceID` 前缀判定（`SWD\`/`ROOT\`/无 `PCI\VEN_`）
- **HAGS 检测**：dxdiag 英文标签 `DriverSupportState` → 读注册表 `HwSchMode`（语言无关）
- **DNS 检查**：`nslookup` 英文失败文本匹配 → 真实 `Dns.GetHostAddresses` 解析
- **UWP 应用检查**：恒返回 false 的假实现 → WinRT `PackageManager` 真实枚举
- **powercfg 错误诊断**：英文关键词 → 中英双语
- **PowerShell 输出**：改 OEM 解码，本地化错误文本不再乱码
- **电源设置**：台式机无电池时 DC 通道返回 null → 接受 null（不动该通道）而非整体拒绝
- **SecureBoot**：传统 BIOS 机器用 `GetFirmwareType` 直接判定 false，不再误锁全部 BCD 操作

## 三、修复假成功/假失败

**问题**：部分"修复"操作执行失败也会报告成功。

**修复**：
- `RepairHelper` 新增返回退出码的命令执行接口，`powercfg /hibernate`、`netsh autotuninglevel` 等失败不再误报"已恢复"
- 服务启动/停止/存在性检查全部改 `ServiceController` API（真实 SCM 状态回读，无文本解析）
- 隐私修复 4 项：PowerShell `Set-ItemProperty`（非终止错误退出码仍为 0 的假成功）→ 注册表直连写入
- per-interface 网络能力零匹配时正确报"不适用"（非 AMD 机器不再假报"已应用"）

## 四、恢复链路加固（数据安全）

- 快照 `checksum` 不匹配不再静默降级使用
- `HasSnapshotAsync` 校验快照内容有效性（零字节/损坏不再计入"有快照"）
- 恢复补 `RequiresAdmin` 权限检查（与应用对称）
- `Changed=false` 的恢复也强制回读验证
- 恢复指针丢失时按能力反查最新可恢复材料（崩溃兜底）
- 系统清理的恢复范围收窄到选中项的 TargetPaths（不再连带恢复全部隔离项）
- 批处理中单条异常不再拖垮整批
- 状态探测不再签发计划/写日志（每次 UI 刷新无副作用）
- 启动和解：非合规但有恢复材料 → 保留"需恢复"标记，不再误标"原始态"
- `DisabledComponents` 等位掩码值改按位合并（不再覆盖其他位）
- 快照保存改原子覆写；基线恢复回滚盲区关闭；自旋锁加 30s 超时

## 五、恢复材料迁移到系统盘

- `Changes`/恢复材料/隔离区清单统一落到 `%LocalAppData%\YuqiEngine`（系统盘）
- 启动时从旧数据根（如 `F:\YuqiEngine`）自动复制迁移，不删源、可重复执行
- 修复跨卷隔离区恢复全灭问题（F:→F: 的旧清单内绝对路径仍可用）
- C: 文件清理不再因"同卷约束"瘫痪

## 九、设计说明（有意为之，非 bug）

- **"恢复不可用"是刻意的安全设计**：没有验证过的改前值回执时，软件拒绝猜测原值，避免覆盖用户/OEM/其他工具的配置。透明卡里会引导用户通过"系统入口"（注册表/命令行）自行调整
- **锁粒度统一**：注册表 DWORD 能力的锁提升到键级，与多值操作正确互斥；身份仍用 ResourceKey，旧恢复材料不受影响
